## 004 error分類と回答

入力:

```md
Call to undefined method App\Models\User::books() が出ます。
```

実出力:

```md
classification: error
reason: エラーメッセージの原因と確認順序を知りたい質問であるため。
need_user_confirmation: false

回答本文:
# 分類
分類: error
分類理由: `undefined method` というエラーメッセージが出ているためです。

# エラーの意味
`User` モデルに `books()` というメソッドが見つからない、という意味です。

# 発生している場所
`$user->books()` のように、Userモデルからbooksメソッドを呼んでいる箇所で起きている可能性が高いです。

# 現時点で分かっていること
Userモデルに対して `books()` が呼ばれている。
ただし、Userモデル内にそのメソッドが存在するかは未確認です。

# つまずき（error）の中核
リレーションはLaravelが自動で作るものではなく、Model内にメソッドとして定義する必要がある点。

# 全体像
Controllerなどで `$user->books()` を使う場合、Userモデル側に `books` リレーションが必要です。

# 原因仮説
1. Userモデルに `books()` リレーションが未定義。
2. メソッド名が `book()` など別名になっている。
3. `$user` だと思っている変数が別のModelになっている。

# 確認する順番
1. Userモデルに `books()` があるか確認する。
2. Controller側の呼び出し名とModel側のメソッド名が一致しているか確認する。
3. `$user` の中身が本当にUserモデルか確認する。

# 理解ステップ
1. エラー文は「呼ばれたメソッドが存在しない」と読む。
2. `App\Models\User::books()` から、Userモデルのbooksメソッドが対象だと読む。
3. LaravelのリレーションはModelのメソッドとして探す。

# 修正案
確認結果に応じて、Userモデルに `books()` リレーションを追加する、またはController側の呼び出し名を既存メソッド名に合わせる。

# 検証方法
同じ操作を実行し、`undefined method` が消えるか確認する。

# 理解確認
このエラー文では、まずどのファイルを確認するのがよさそうですか。
```

判定: PASS
