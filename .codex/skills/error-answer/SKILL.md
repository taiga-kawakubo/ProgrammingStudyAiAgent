# 目的

エラー文、実行状況、提示コードから、原因を断定せず、エラーの意味、発生場所、原因仮説、確認順序、修正案、検証方法を整理する。

# 入力

- エラーメッセージ
- 実行した操作やコマンド
- 提示コード
- 許可済み参照範囲
- 環境情報
- classifier Skillの分類結果と分類理由

# 出力

```md
# 分類
分類:
分類理由:

# エラーの意味
# 発生している場所
# 現時点で分かっていること
# つまずき（error）の中核
# 全体像
# 原因仮説
# 確認する順番
# 理解ステップ
# 修正案
# 検証方法
# 具体例（他でも使える考え方）
# 次に同じ問題が出たら見る順番
# 理解確認
```

# 処理手順

1. 冒頭で分類と分類理由を短く表示する。
2. エラー文が何を示しているかを説明する。
3. 発生場所として考えられるファイル、処理、環境を整理する。
4. 現時点で確実に分かることを示す。
5. 原因を可能性の高い順に仮説として出す。
6. 最初から修正コードを出さず、確認する順番を示す。
7. 確認結果に応じた修正案を出す。
8. 修正後の検証方法を示す。
9. 再発防止につながる考え方を示す。
10. 最後に軽い理解確認を1つ出す。

# 禁止事項

- 原因を断定しない。
- 最初から修正コードだけを提示しない。
- 未確認のファイルや環境を見た前提にしない。
- ファイルを直接作成、更新、削除しない。

# メインAgentへ返す管理情報

- 理解度候補
- 苦手の具体内容候補
- 苦手傾向タグ候補
- 学習ログ化候補
- 追加で確認したい参照範囲
- 検証コマンド候補

# ダミー検証

```md
1. 「Call to undefined method App\Models\User::books() が出ます」
期待値: リレーション未定義、メソッド名違い、Model確認の順に仮説を出す。

2. 「404 Not Found になります」
期待値: URL、Route、HTTPメソッド、Controller、キャッシュの順に確認する。

3. 「SQLSTATE[42S02]: Base table or view not found が出ます」
期待値: テーブル未作成、migration未実行、テーブル名違いを仮説として整理する。
```

# 合格条件

3件すべてで、エラーの意味、原因仮説、確認順序、修正案、検証方法が出る。

# 不合格時の修正方針

期待値と実出力がずれた場合は、原因仮説、確認順序、修正案、検証方法を修正し、同じダミー入力で再検証する。
合格するまで次のSkillへ進まない。
