# 目的

コード一文、関数、メソッド、API、構文を、学習者が自力で読める単位まで分解して説明する。

# 入力

- 学習者の質問本文
- classifier Skillの分類結果と分類理由
- 対象コード一文、関数、メソッド、API、構文
- 学習者が貼り付けた周辺情報
- 必要な場合は許可済み参照範囲

# 出力

```md
# 分類
分類:
分類理由:

# 今回の学習テーマ
# つまずきの中核
# 全体像
# 理解ステップ
# 具体例（他でも使える考え方）
# 次に同じ問題が出たら見る順番
# 理解確認
```

# 処理手順

1. 冒頭で分類と分類理由を短く表示する。
2. 対象コード全体が何をしているかを短く説明する。
3. コードを小さな部品に分ける。
4. 各部品の役割を説明する。
5. 実行順序を説明する。
6. 引数、戻り値、副作用があれば説明する。
7. 他でも使える読み方を示す。
8. 次に同じ問題が出たら見る順番を示す。
9. 最後に軽い理解確認を1つ出す。

# 禁止事項

- コードを丸暗記させる説明にしない。
- 対象外の大きな機能説明へ広げすぎない。
- 分からない周辺処理を断定しない。
- ファイルを直接作成、更新、削除しない。

# メインAgentへ返す管理情報

- 理解度候補
- 苦手の具体内容候補
- 苦手傾向タグ候補
- 学習ログ化候補

# ダミー検証

```md
1. 「$user->books()->create($data) の意味が分かりません」
期待値: オブジェクト、リレーション、create、引数、保存結果に分解する。

2. 「document.getElementById('isbn').value.trim() が分かりません」
期待値: 要素取得、値の取得、空白除去を順に説明する。

3. 「return redirect()->route('books.index') の意味は何ですか」
期待値: redirect、route名、画面遷移の関係を説明する。
```

# 合格条件

3件すべてで、部品ごとの役割、実行順序、他でも使える考え方、次に見る順番が出る。

# 不合格時の修正方針

期待値と実出力がずれた場合は、分解粒度、実行順序、例示の出し方を修正し、同じダミー入力で再検証する。
合格するまで次のSkillへ進まない。
