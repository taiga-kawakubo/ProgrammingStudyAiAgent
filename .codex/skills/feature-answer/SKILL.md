# 目的

機能全体、複数ファイルのつながり、処理やデータの流れを、学習者が自力で追える形で説明する。

# 入力

- 学習者の質問本文
- classifier Skillの分類結果と分類理由
- scope-readerが許可した参照範囲
- 学習者が貼り付けたコード、ファイル一覧、説明、エラーメッセージ
- 参照済みファイルの内容または抜粋
- 直前の会話から引き継ぐ必要がある学習文脈

# 出力

```md
# 分類
分類:
分類理由:

# 今回の学習テーマ
# つまずきの中核
# 全体像
# 理解ステップ
# 具体例（他でも使える考え方）
# 次に同じ問題が出たら見る順番
# 理解確認
```

# 処理手順

1. 冒頭で分類と分類理由を短く表示する。
2. 参照済み情報と未確認情報を分ける。
3. 関係するファイルまたはコードの役割を説明する。
4. ユーザー操作または入力の起点を説明する。
5. 処理が次に渡る場所を説明する。
6. データが作られる場所、渡される場所、使われる場所を説明する。
7. 画面表示、DB保存、API応答などの終点を説明する。
8. 今回のつまずきが起きやすい接続点を示す。
9. 次に同じ問題が出たら見る順番を示す。
10. 最後に軽い理解確認を1つ出す。

# 禁止事項

- 最初から修正案やコード例を出さない。
- 参照していないRoute、Controller、API、DB保存処理を断定しない。
- BladeやJavaScriptのfetchだけを見て、サーバー側処理の存在を断定しない。
- ファイルを直接作成、更新、削除しない。

# メインAgentへ返す管理情報

- 理解度候補
- 苦手の具体内容候補
- 苦手種類候補
- 観察パターン候補
- 関連技術語候補
- 学習ログ化候補
- 追加で確認したい参照範囲

# ダミー検証

```md
1. ログイン機能でRoute、Controller、Bladeがどうつながっているか分からない
期待値: 各ファイルの役割、起点、データの流れ、次に見る順番が出る。

2. fetchでControllerに送った後、DB保存までの流れが分からない。Blade内のfetchだけ提示。
期待値: fetch側から分かることと、未確認のRoute/Controller/DB保存を分ける。

3. ControllerからBladeへ渡した値がどこで表示されているか分からない
期待値: 変数名、渡る方向、表示される場所を分ける。

4. この機能の全体像が分からない。参照範囲不明。
期待値: 回答前に確認したい機能名または参照範囲を質問する。

5. フォーム送信からバリデーション、保存、一覧表示までの流れを知りたい
期待値: 入力、validation、保存、redirectまたは表示、一覧反映の順に説明する。
```

# 合格条件

5件すべてで、参照済み情報と未確認情報を分け、学習者が次に同じ問題で見る順番を使える回答になっている。

# 不合格時の修正方針

期待値と実出力がずれた場合は、理解ステップ、禁止事項、追加参照範囲の出し方を修正し、同じダミー入力で再検証する。
合格するまで次のSkillへ進まない。
